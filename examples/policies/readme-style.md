# README writing style

Write READMEs like landing pages, not API docs. The reader decides in 3?5 seconds.

- Bold one-liner first: what it does and why it matters.
- Working code example in the first 5 lines.
- Prefer two-column feature tables over long Feature bullets.
- Quick Start copy-paste ready. No `$` prefix on bash commands.
- Vary sentence length.
- Avoid empty marketing words: seamless, robust, comprehensive, cutting-edge.
- Never open with "In today's?" or close with "Happy coding!".
- Only link screenshots/gifs that exist on disk.
